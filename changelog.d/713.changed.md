This release starts a new cache epoch. Changes below alter the bytes served for URLs that already exist (aspect crops, the redaction filters and watermarks or overlays placed off the canvas on a source that is not 8-bit RGBA, which keep the source's layout and depth; `quality(auto)` JPEG output with a `fill`, which is scored against the image as the file holds it; `sharpen` past 255 and `huerotate` past a full turn; `blur_region` and `blurclass` boxes more than 240 px on their shorter side; video output of a smart crop; class redaction past 64 detections with a segmentation model; and progressive JPEG sources with restart intervals, or with a first scan the full-size decoder refuses, whose first operation is a resize to a third of their size or less, all issue #713), so the rendering version in the configuration fingerprint moves from 7 to 8 and the default configuration no longer prints the 0.13.1 fingerprint, `25e5e3685efb9abe`. The first start on this version begins a new epoch: entries written by 0.13.1 and earlier stay in the disk and shared tiers under their old keys, unreachable, until they age out, and during a rolling upgrade old and new replicas read and write separate entries instead of serving each other's renders. Expect a cold cache after the upgrade: every cached render is made again once, in every format. The epoch does not reach a CDN in front of the server: a response a CDN stored before the upgrade stays until it expires or is purged.
