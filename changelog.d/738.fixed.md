A server whose standard error had no reader left (a log collector that exited)
no longer panics at its next line there (issue #738). Its warnings, errors and
shutdown lines on stderr were written with `eprintln!`, which panics when a
write fails, so such a stderr ended the boot at its first warning, and a
request at its first error line. A line that cannot be written is now dropped,
standard output says so once, and the server boots, serves and stops as it
would. Each later line is tried again, so the lines come back if stderr does.
