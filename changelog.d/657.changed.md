A resize of a source with transparency no longer copies the frame to
premultiply it (issue #657). The resize backend resamples alpha
premultiplied, and it premultiplied a borrowed frame into a second buffer
the size of the frame: 15 MB allocated, zeroed and written for a 2400x1600
RGBA source. The size and fit-in operations own the frame they resize, so
it is now premultiplied where it sits by the backend's own routine,
resampled with the backend's alpha step off, and divided back by the
backend's own routine: the same three steps on the same values. `800x0` of
a 2400x1600 RGBA8 source went from 14.7 to 6.8 ms in the pipeline, and the
step's peak memory falls by one frame. A source without alpha takes the
path it took. Responses are unchanged.
