A request's operations are parsed once, not three times (issue #640). The
server walked every remainder to collect its preset names, again to expand
them, and a third time to parse the expansion, then built the cache key
from a string for every segment and every filter. A remainder that names no
preset is now parsed in one walk, and the canonical form and the cache key
are written into one buffer. Verifying and keying a signed URL with a
fit-in, eleven filters, `exp:` and `maxage:` went from 5.86 to 3.54 µs. A
URL that names a preset, and any URL the server refuses, takes the three
walks as before, so every error, and the order errors win in, is unchanged.
So is every cache key, byte for byte: entries in the disk and shared tiers
keep serving. In the library, the new `crabcrop::url::parse_without_presets`
is that one walk. Responses are unchanged.
