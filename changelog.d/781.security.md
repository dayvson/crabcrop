The shared result tier and the upload bucket no longer follow a store's redirects (issue #781). Both clients followed a `3xx` to the host it named, with the session token (`x-amz-security-token`) and `x-amz-date`, and sent a write's body again; only `Authorization` was dropped. A `3xx` is now the store's answer, a refusal like a `403`, and nothing is sent to the host it names: a lookup is a miss that counts in `crabcrop_cache_tier_errors_total` and `crabcrop_cache_shared_refused_total{request="lookup"}`, a write is dropped and counted, a purge scan that meets one stays incomplete and keeps its tombstone in force, an upload's existence check counts in `crabcrop_upload_exists_checks_failed_total`, and an upload's write answers `502 upload_store_unavailable`, each logged as the other refusals are. The source loader's store client and the container credentials client already refused redirects.
