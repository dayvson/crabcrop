The aesthetic head loader refuses a file over its 16 MiB budget from the file's size, before reading it (issue #783). `AestheticHead::load` read the whole file `CRABCROP_AESTHETIC_HEAD` names and only then compared its length with the budget, so a head path pointed at a large file, such as a model save, held the whole file in memory at boot before the refusal. The loader now checks the size the file system reports first, and reads at most one byte past the budget, so a file that grows after the check, or a device that reports no size, is refused the same way. A head within the budget loads as before. No other checkpoint file is read this way: the checkpoint reader parses the head file alone.
