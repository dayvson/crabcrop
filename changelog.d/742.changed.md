Every HTTPS connection the server opens now takes its cryptography from ring,
and the binary no longer carries AWS-LC (issue #742). Source fetches and bucket
requests used aws-lc-rs while the C2PA timestamp authority's client used ring,
so the binary compiled both, and a TLS or cryptography advisory had to be
checked against each. The cipher suites are the same. Two things change for
source fetches and bucket requests, where ring supports less than aws-lc-rs:
they no longer offer the X25519MLKEM768 post-quantum key exchange, which they
listed last of four groups, after X25519, P-256 and P-384; and a server whose
certificate has an ECDSA P-521 or ML-DSA key now fails the handshake, as does,
on Linux, a certificate chain signed with ECDSA P-521, ECDSA over SHA-512 or
ML-DSA. Such a fetch answers `502 source_fetch_failed`. The release build
compiles 485 crates instead of 494, and a source build no longer compiles
AWS-LC's C and assembly.
