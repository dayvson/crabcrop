A meta document's annotation sections now decode the render on the blocking pool, in the task that runs the first section's model, where it was decoded on a runtime worker before that task started (issue #736). While a large render decoded there, it held that worker from every other request scheduled on it. A decoder that panics on the render is caught in that task now: the sections that need the pixels answer as they do for a render that does not decode (tags and detections are left out, and moderation, the embedding and OCR report `inference_failed`), and the document still answers `200`. As for a render that does not decode, each of those sections tries the decode itself, so stderr gets the panic's report and the line `meta: decoding the render panicked; the sections that need its pixels answer without them` once for each section that tried. The panic used to end the request's task, and the client got no answer. The annotation deadline now also ends the wait for a decode still running: measured with a 2-second decode and a 300 ms deadline, the document answered after the decode, at 2 seconds, and now answers at 300 ms, with the tags and detections left out and moderation, the embedding and OCR reported `timed_out`. The render is still decoded once for all the sections of a document (issue #676), and a document whose sections answer in time is the same bytes as before.
