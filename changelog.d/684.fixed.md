The MCP server's test suite no longer races with itself, and a server that fails to start no longer hangs the run (issue #684). `npm test` in `sdks/mcp` ran its two test files at once: one runs `npm pack`, which rebuilds `sdks/typescript/dist`, and the other starts servers that load that `dist`. A server that started while a file was being rewritten loaded an empty module and exited, its test waited out a 60-second timeout without cleaning up, and the run then stayed open until the CI job's time limit, which reported "cancelled" with no failed test. The files now run one after the other, and the test client fails a request as soon as its server closes its output. Nothing shipped changes.
