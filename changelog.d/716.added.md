The Python SDK gains the TypeScript SDK's typed operation builders and names,
and its package carries current metadata (issue #716). `ops`, `filter` and
`join_ops` build operation strings as the TypeScript `ops`, `filter` and
`joinOps` do, under Python names (`ops.crop_objects`,
`filter.quality_per_format`, keyword arguments for an options object), beside
`MAX_DIMENSION`. They run the builder cases of `spec/operation-vectors.json`
that the TypeScript SDK runs, so the two SDKs spell every operation alike,
32-bit float arguments included, and a value the server would refuse raises
`ValueError`. `seal` is the TypeScript and Rust name for sealing a remainder;
`seal_url`, its earlier Python name, still works. `build_srcset` takes a
`key_id`, as the TypeScript `buildSrcSet` does. The package ships `py.typed`,
has a `__version__` that `scripts/bump_version.py` moves with the release
version, and lists its API in `__all__`, so `from crabcrop_url import *` no
longer brings in the modules it imports. `pyproject.toml` states the license
as the SPDX expression `MIT` (PEP 639) instead of the legacy table, which
needs setuptools 77 or newer to build, and its classifiers name Python 3.9 to
3.14 and `Typing :: Typed`. A Python explainer follows issue #712, which
changes the explainer's number rules.
