A purge and an upload overwrite now reach every spelling of a source that the loader fetches as one object (issue #778). Cache entries were keyed on the source as the request wrote it, so `file:///photo.png`, `file://localhost/photo.png` and `file:///./photo.png` were three entries for one file, and `http://example.com/f/./a.jpg` was an entry of its own beside `http://example.com/f/a.jpg`: a replacing upload purged the renders of the one spelling it hands back, a purge only those of the spelling it named, and the others kept answering the old render with the old `ETag`. Entries are now keyed on the source in the form the loader fetches: an `http://` or `https://` URL as the URL it requests, with the scheme and host in lower case, no default port, its dot segments resolved and no fragment; a `file://` URL as the path below the file root that it opens, decoded; and an `s3://` or `gs://` URL as written. The purge by URL, the purge an overwrite runs, and `/explain`'s canonical form use the same form. Keys of sources already in that form do not change, and a render cached under any other spelling is made again once after the upgrade.
