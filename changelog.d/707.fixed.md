An image request whose client goes away before its answer now leaves its log
line and its metrics update, with the status `499` (issue #707). Since 0.11.0
a render that has started outlives its client and is stored, but the request
was dropped with its record, so it left neither, and nor did the requests
waiting on its render whose clients gave up too, a miss dropped before its
render started, or a meta or debug request dropped mid-render. Each now
records itself when the server stops working on it: at once for a request that
stops where it is, and once its render is stored for a render that finishes for
nobody, with its load and render times. `499` is the "client closed request"
of nginx's logs: no response carries it, it counts in `status_class="4xx"`,
and such a request served no bytes. A request whose client gives up while it
waits for room in the log's queue was never handled and leaves nothing, as
before. A request line also names its method: a `HEAD` request, which the
image route answers too, was logged as `GET`. And a server whose standard
output had no reader left during boot (a log collector that exited) no longer
panics at its first boot line: a boot line that cannot be written is lost,
stderr says so once, and the server boots and serves, the request log counting
the lines it cannot write as it does once the server serves.
