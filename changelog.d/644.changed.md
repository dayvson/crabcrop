A disk-tier entry is read into a buffer sized once (issue #644). The read
started from an empty buffer and doubled it, about a dozen `read` calls and
as many reallocations for a 20 KB entry, though the open had already read
the file's length. The buffer is now sized from that length: reading a
20 KB entry went from 4.70 to 2.15 µs, about 3% of a disk-tier hit, and a
1 MB entry from 73.0 to 67.0 µs. A file past the tier's size cap is refused
before it is read, and the read is still capped, so one that grows past the
cap while it is read is refused as before. The shared tier no longer hashes
an empty body on every read: a request with no body names the SHA-256 of
nothing from a constant. The entry format, the MAC check on every read, the
size cap, the open that cannot wait on a FIFO, and the bytes and signatures
sent to the bucket are unchanged.
