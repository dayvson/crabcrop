`contrast(0)` is now the identity, where its lookup table dropped the values 1 to 63 one level each (issue #815). The table scales a channel about the midpoint by `((100 + amount) / 100)^2`; at amount 0 that factor is one, so the table should map every value to itself, but it was built in `f32` and truncated, so `1/255` became `0.99998` and each of the values 1 to 63 came out one level low while every other value mapped to itself. The amount is now special-cased to the identity table, so `contrast(0)` changes no pixel and is skipped on an 8-bit RGB image like the other filters at their no-op argument; every other amount keeps the image crate's formula and its rounding, byte for byte. A render that applies `contrast(0)` now serves different bytes, which the new cache epoch covers (see the Changed entry for issue #793). No upgrade-corpus entry uses `contrast(0)`, so none is re-baselined.
