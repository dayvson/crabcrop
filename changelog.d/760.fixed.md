A head file (`CRABCROP_AESTHETIC_HEAD`) whose pickle uses a value from below a
MARK now fails boot with a configuration error, where it panicked (issue #760).
The restricted pickle reader let an opcode after a MARK take values pushed
before it, which Python's unpickler refuses, and the TUPLE or SETITEMS that
closed the MARK then found it past the top of the stack and panicked. The
reader now refuses such an opcode as Python does, and the boot stops on the
error other malformed head files get, attributed to `CRABCROP_AESTHETIC_HEAD`,
which names the opcode: `cannot load the aesthetic head: the aesthetic head
<path> is not usable: a pickle BUILD uses a value from below an open MARK`. A
head file that loaded before although Python refuses it, such as one with a
stray MARK before its closing BUILD, now fails the same way; the two LAION
heads load as before. The reader also read NEWTRUE as false and NEWFALSE as
true, the reverse of Python, and now reads them as true and false. No value a
head is loaded from is a bool (the two in each LAION head are the requires-grad
flags of its tensor rebuilds, which the reader ignores), so no head loads
differently.
