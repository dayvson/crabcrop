In the library, `crabcrop::server::AppState` is no longer `Clone`, and its
eighteen provider and renderer handles, from `removebg` to
`provenance_signer`, moved into the new `crabcrop::server::Providers`, which
the state holds as `providers: Arc<Providers>` (issue #475). Read a handle as
`state.providers.face`. `crabcrop::server::app` takes anything that converts
into an `Arc<AppState>`, an `AppState` included, so the call `app(state)` is
unchanged. A caller that builds a state field by field puts the eighteen
handles in a `Providers`, or `Arc::new(Providers::default())` when none is
configured, and one that cloned the state to keep a handle wraps it in an
`Arc` and clones that. The server used to copy the whole state, about fifty
fields with the presets and source-root maps, the keyring's secret bytes and
the configuration strings, into each of its routes, again for every request,
and again for each task a miss, a disk lookup or a purge starts. It now holds
one state behind an `Arc`, so each of those copies a pointer, and each engine
job shares the state's providers instead of copying every handle. Responses,
headers, metrics and log lines are unchanged.
