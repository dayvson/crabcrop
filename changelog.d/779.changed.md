The docs now say that the shared result tier has no size bound, and what a purge costs against it (issue #779). Renders are written through to `CRABCROP_RESULT_BUCKET`, and nothing counts or evicts what the bucket holds, so docs/deployment.md (Bounding the shared tier) recommends an S3 lifecycle rule that expires the entry objects and leaves the purge tombstones alone. The server ends the prefix with one `/`, so with `CRABCROP_RESULT_PREFIX=cache` the entries are the objects `cache/<64 hex digits>.bin` and the tombstones sit under `cache/purges/`. A lifecycle filter is a prefix and `purges/` sits inside the result prefix, so that takes 16 rules, on `cache/0` to `cache/9` and `cache/a` to `cache/f`. Every purge lists every object under the prefix, one LIST request per 1,000 objects, and reads the header of each entry with one ranged GET, so its cost grows with the bucket as well.
