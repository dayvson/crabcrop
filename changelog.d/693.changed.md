Every AI model now runs on one ONNX Runtime thread pool, a thread per core,
instead of a pool of its own (issue #693). By default the runtime gave each
session a pool with a thread per core, its workers pinned to cores 1 and up
and spinning for a while after each operator, so two inferences at once,
which the AI gate allows, ran two pools' workers on the same cores. On a
4-core host, four AI requests at once (a smart crop, `removebg`, `studio`
and an `objects` crop, each a cache miss) took 433 ms where they took
534 ms (1.27x). One request at a time is unchanged within the spread
(1.02x), and so is a single inference, except MobileSAM's two models
(`segment`, 1.08x). The pool's threads are not pinned. Responses are
unchanged.
