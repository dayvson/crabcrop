A `CRABCROP_PDF_RENDERER` that runs but cannot render a page now stops the boot (issue #715). Boot checked only that the renderer and its `pdfinfo` sibling exist and are executable. Poppler's `pdftoppm` passed that: it sits next to `pdfinfo` and takes the renderer's arguments, but writes its PNG to a file instead of standard output, so every `page:` request answered `502`. Boot now renders a one-page test document through both programs and decodes the PNG, and a pair that fails stops the boot with an error that names the variable and what went wrong. `pdftocairo` passes, in a few tens of milliseconds, and a renderer that hangs holds the boot for `CRABCROP_PDF_TIMEOUT_SECS` at most. In the library, the new `crabcrop::pdf::PdfRenderer::self_test` is that check.
