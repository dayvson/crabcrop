The MCP server handles batches, tool errors, notifications and responses as
JSON-RPC and MCP specify (issue #716). A batch, a JSON array of messages, which MCP
2025-03-26 requires a server to accept, gets one array of answers, where it
was dropped. A `tools/call` that names a tool the server does not have, has
no tool name string, or has `arguments` that are not an object is a `-32602`
error, as the spec's tools section has it, where it was a tool result with
`isError`; a bad argument value is still a tool result the model can read. A
request whose `id` is null, which MCP forbids, or is not a string or a number
gets `-32600`; one with a null id was handled as a notification. A
notification gets no answer and now runs nothing, so a `tools/call` sent
without an `id` no longer purges or fetches while telling nobody. A response
from the client, to a request this server never sends, gets no answer, where
it got an empty result. sdks/mcp/README.md lists the codes. The MCP package
now builds with the TypeScript SDK's compiler and checks: TypeScript 7.0.2,
where it had 5.9.3, with `strict`, which it had off, and, in both packages,
`noUnusedLocals`, which found the unused import the looser settings hid.
