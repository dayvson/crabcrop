A page rendered by the stock Poppler `pdftocairo` now comes back as an uncompressed TIFF rather than a PNG (issue #786). Poppler's PNG writer was the bulk of a photographic page's render: at 144 dpi, a page holding a 2400x1600 photograph took about 3.62 s to write as a PNG and about 0.11 s as an uncompressed TIFF, and the corpus's text page 97 against 30 ms; decoding the TIFF in crabcrop costs a few milliseconds more, well under what the writer saves. The render now asks for `-tiff -tiffcompression none`, and because a TIFF writer seeks its output to patch the header, which a pipe cannot do, the renderer's stdout is a seekable in-memory file (a memfd on Linux) capped with `RLIMIT_FSIZE`, beside the other caps the renderer runs under; peak memory at the raster limit grows by the uncompressed raster. Only the stock `pdftocairo` moves to the TIFF contract: any other `CRABCROP_PDF_RENDERER`, a custom wrapper among them, keeps the documented PNG interface on a pipe, so an integration built to it goes on working. The rendered page's source format is still read as PNG, so a page's default output format is unchanged, and the TIFF decodes to the same frame as the PNG, so rendered output is byte-for-byte identical. The renderer contract in docs/media.md is updated.
