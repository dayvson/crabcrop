A `quality(auto)` search prepares its SSIMULACRA2 reference once (issue
#664). For JPEG and JPEG XL the search encodes, decodes and scores up to
four candidates against the processed image, and every score prepared that
image for the metric again: linear light, XYB, the six-scale pyramid and
two of the five blurs at each scale, 14 ms of a 45 ms score at 800x533. The
reference is now prepared at the first score, used for the later
candidates and for the score after a `max_bytes` ladder, and dropped when
the encode returns. An encode that scores nothing never builds it. A search
over an 800x533 photograph went from 151.8 to 122.2 ms and one over a
2400x1600 output from 2,067 to 1,618 ms. The scores are the same bit for
bit, so a search takes the same steps and serves the same bytes, quality
and score. The four-candidate limit, the request's encode budget and the
deadline check before each candidate are as they were. The prepared
reference takes 48 bytes for each pixel while the search runs, which each
score used to build and free; the peak memory of a search stays within a
few percent of what it was. In the library, the new
`crabcrop::quality::SsimReference` is that reference. Responses are
unchanged.
