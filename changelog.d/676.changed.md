A meta document decodes its render once, and the object detector fills
and reads its tensors by rows (issue #676). Tags, detections, moderation,
the embedding and OCR each decoded the rendered bytes for themselves, one
after the other, and detections copied the decoded frame once more for
every configured detector: a document with all five sections decoded the
same image five times, 16 ms each for a 2400x1600 JPEG render. The first
section that needs pixels now decodes the render and the others read that
frame, as do the detectors. Each section still takes its own inference
permit, runs under the annotation deadline, and reports its own failure
when the render does not decode. In the detector, the letterboxed input is
filled a row at a time, the best class of each candidate is found class
row by class row, and the model's 2.8 MB output is read in place instead
of copied. A meta document with detections, moderation and OCR went from
276 to 232 ms on a 2400x1600 JPEG render, and a detection on an 810x1080
photo from 42.2 to 40.9 ms. The sections see the pixels they decoded
before and the detector picks the same classes and scores, ties and NaN
included. Responses are unchanged.
