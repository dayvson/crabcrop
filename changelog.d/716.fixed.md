The MCP server answers malformed and unknown requests with JSON-RPC errors,
and negotiates the protocol version (issue #716). An unknown method got an
empty result, as if it had succeeded; it now gets `-32601`. A line that is
not JSON got no answer, so the client waited on a request it could not name;
it now gets `-32700` with a null id. Valid JSON that is not a request object,
such as a bare `null`, ended the process: reading its id threw inside the
request chain, and the unhandled rejection stopped the server. It now gets
`-32600`, and an error while answering one line no longer stops the lines
after it. `initialize` answered protocol version 2024-11-05 whatever the
client asked for. It now answers with the client's version when the server
speaks it (2025-11-25, 2025-06-18, 2025-03-26 or 2024-11-05), and with
2025-11-25 otherwise, as the spec's version negotiation says. The source
header no longer says the server has no dependencies: it bundles
`@crabcrop/url`.
