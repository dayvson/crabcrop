An 8-bit `upscale` no longer makes a libm call for every output sample
(issue #675). The provider turned the model's float output into pixels one
sample at a time, rounding each with `f32::round`, which is a call into
libm on the baseline x86-64 target: 2 million calls for a 960x720 result,
and a loop the compiler cannot vectorize. The 8-bit conversion now rounds
with one comparison: the clamped value is in 0..=255, so its integer part
is the truncating cast and the difference to it is exact. The output
planes are converted a block at a time and the input tensor is filled a
row at a time. With the small x2 model the ai-models workflow builds,
`upscale(2)` of a 480x360 photo went from 15.3 to 12.6 ms; behind a
production super-resolution model, which spends seconds in inference, the
change is not measurable. The model is fed the same tensor and every
output sample rounds as it did, NaN and the infinities included, so the
result is the same byte for byte. 16-bit and float sources take the same
path with their own conversions. Responses are unchanged.
