A request that panics while it runs an AI model no longer leaves that model failing every later request until a restart (issue #715). The panic poisoned the lock on the model's session, and from then on each of the 14 places that take such a lock, the sessions and the CLIP embedding memo, failed: a render answered `500 inference_failed` and a meta annotation was left out, with nothing on `/health` or `/metrics` to show it. A run never changes a session, so the next request that needs the model now takes the lock back and runs it, and stderr gets one line for each such panic, with a count since boot. The face and detection providers, which left their frame memo out once their session was poisoned, keep using it. In the library, `crabcrop::ai::AiError::LockPoisoned` is removed, since nothing returns it.
