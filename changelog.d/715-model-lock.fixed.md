A request that panics while it runs an AI model no longer leaves that model failing every later request until a restart (issue #715). The panic poisoned the lock on the model's session, and each of the 14 places that take such a lock, the sessions and the CLIP embedding memo, then answered `500 inference_failed`, with nothing on `/health` or `/metrics` to show it. A run never changes a session, so the next request that needs the model now takes the lock back and runs it, and stderr gets one line for each such panic, with a count since boot. The face and detection providers, which left their frame memo out once their session was poisoned, keep using it.
