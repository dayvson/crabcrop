Signing an output no longer has the C2PA SDK validate the manifest it has
just signed, unless a timestamp authority is configured (issue #669). That
validation took about half of a signature: signing an 800x533 JPEG output,
with its 1.15 MB source as the parent ingredient, went from 1.42 to 0.71 ms
on a 4-core VM (1.99x), and a PNG output from 1.60 to 0.88 ms. In exchange
the boot self-test now also signs one manifest of each of the six shapes the
server writes (with and without a parent ingredient, with the parent's
recorded validation status, each with and without the AI edit action), with
that validation on, and a shape the SDK refuses stops the server from
starting, with the shape named. With `CRABCROP_C2PA_TSA_URL` set nothing
changes: every signed output is still validated before it is served. What is
written into an output is unchanged, and a key that does not match its
certificate or a bare self-signed certificate is still refused at boot.
