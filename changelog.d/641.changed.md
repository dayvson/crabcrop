A cache hit no longer copies its request's headers or prepares for a miss
(issue #641). The image handler took copies of the request's URI and
headers and copied `Accept` and `If-None-Match` again. Before the cache
lookup it built the text a flight's followers are matched by, and cloned
the cache key and the cache groups, which only a miss uses. It built
`Cache-Control` as a string to parse it back, and scanned it on every
answer for two directives it rarely needs. The handler now reads the
request in place, a request builds that text only once it leads or follows
a flight, the constant header values are constants, and the two scans run
when their answer is used. A memory-tier hit in process went from 7.92 to
6.75 µs. Identical concurrent misses still share one fetch and one render.
Responses, headers, log lines and metrics are unchanged.
